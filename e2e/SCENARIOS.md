# Интеграционные сценарии (E2E)

Этот файл фиксирует пользовательские сценарии, которые покрываются автоматическими
интеграционными проверками в [`booking.spec.ts`](./booking.spec.ts).

Тесты запускают реальный браузер (Chromium) через Playwright против полного стека:
Vue-фронтенд (`:5173`) + NestJS-бэкенд (`:4010`) + изолированная SQLite-база
`backend/booking.test.sqlite` (очищается перед каждым запуском).

## S1. Основной путь бронирования (happy path)

**Действующее лицо:** гость.

**Предусловие:** в каталоге есть как минимум один тип события (создаётся в
`global-setup.ts` перед стартом тестов).

**Шаги:**

1. Гость открывает главную страницу `/` и видит карточку типа события в каталоге.
2. Нажимает «Выбрать слот» в карточке — открывается страница `/book/:id`.
3. На странице бронирования выбирает первое доступное окно из списка
   («Доступные окна · Ближайшие 14 дней»).
4. Открывается диалог «Забронировать встречу». Гость заполняет имя и email и
   нажимает «Подтвердить».

**Ожидаемый результат:**

- Диалог закрывается, происходит переход на `/`.
- Появляется уведомление об успехе со словами «Бронирование создано».
- На бэкенде `GET /bookings` возвращает ровно одну запись с тем же `guestEmail`,
  `eventTypeId`, `startTime`, `endTime`.

## S2. Конфликт при гонке за слот

**Действующее лицо:** гость, который проиграл гонку.

**Предусловие:** в каталоге есть тип события (тот же, что в S1).

**Шаги:**

1. Гость открывает `/book/:id`, выбирает первое доступное окно.
2. В открывшемся диалоге заполняет имя и email — но **не подтверждает**.
3. Параллельно второй клиент бронирует ровно тот же `startTime`/`endTime`
   напрямую через `POST /bookings` (имитация гонки в e2e через Playwright
   `request`-контекст).
4. Гость нажимает «Подтвердить» в своей форме.

**Ожидаемый результат:**

- Бэкенд возвращает `409 booking_conflict`.
- Фронтенд показывает уведомление «Слот только что заняли · Выберите другое время»
  (см. [`BookView.vue`](../front/src/views/BookView.vue)).
- Список доступных слотов автоматически обновляется и занятого слота в нём
  больше нет (инвалидация `event-types/:id/slots`).

## Что вне scope этого набора

- Сценарии владельца (создание `EventType` через UI) — покрыты юнит-тестами и
  валидируются вручную.
- Визуальная регрессия / скриншот-сравнение.
- Кросс-браузерные прогоны (Firefox/WebKit) — конфигурация позволяет включить
  при необходимости.
